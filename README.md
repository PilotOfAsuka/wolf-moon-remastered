# Wolf Moon — широкий Classic на Godot

Рабочий Godot 4.7.2 проект оригинальной Wolf Moon 1.06. Текущая визуальная цель по последнему указанию пользователя — красивый **широкий Classic**, без 3D, HD-замен, растягивания спрайтов и добавленных световых эффектов. Неподтверждённые требования перечислены в `REMAINING_WORK.md`. Сам JAR и исследовательские материалы в репозиторий не входят; для запуска проекта/готовой web-версии JAR не нужен.

## Запуск

- Двойной щелчок по `Запустить Wolf Moon.command` запускает проект установленным Godot.
- Либо импортировать `game/project.godot` в Godot 4.7.2 и нажать F6/F5 для запуска сцены/проекта.
- Локальная самостоятельная сборка macOS располагается в `build/Wolf Moon.app`, когда экспорт успешно завершён; её проверка отражается в `docs/PLATFORMS.md`.

## Управление

Стрелки/WASD — исходные шаги и повороты; Enter/пробел — действие; Esc — меню; Tab/Backspace — правая функциональная клавиша. Цифры сохраняют оригинальные функции. Down/8 действует по правилам телефона, включая разворот, а не произвольное движение назад.

**F2** — плавно переключить оригинальный экран / широкий Classic в текущем состоянии игры. Такая же кнопка есть на экране. F5 — полное быстрое сохранение, F9 — загрузка. Оригинальные сохранения во время отдыха также работают. Есть экранные клавиши и кнопки геймпада; проверка на физическом геймпаде пока не проведена.

## Что реализовано

- Свежая инвентаризация всех 88 записей JAR, 17 классов, 417 записей спрайтов; CFR + полный `javap -verbose`.
- Полное декодирование карты 30×40, существ, предметов, объектов, десяти таблиц декораций, девяти меню и 233 текстов на каждом из двух языков.
- Перенос исполняемой логики в переносимое GDScript-ядро совместимости. В рантайме Java не нужна: исходные JVM-инструкции исполняет `game/core/bytecode_vm.gd`. Новые правила боя, ИИ, карт или сюжетных веток не выдуманы.
- Рабочая исходная перспектива от первого лица, меню, вступление, перемещение и сохранения.
- Classic использует исходные ресурсы и целочисленное масштабирование. Шрифт Java ME зависел от устройства, поэтому современная растеризация шрифта пока не является OEM-эталоном.
- Широкий Classic повторно рисует **тот же список операций исходного псевдо-3D-движка** на широком холсте. Составные спрайты сохраняют пропорции и целочисленный пиксельный масштаб. Фоновые материалы заполняются тайлами в пределах исходной клетки вместо растягивания текстур. Порядок перекрытия и игровой отбор клеток сохранены.
- HD- и 3D-эксперименты отключены по уточнению пользователя и оставлены только в локальном архиве исследований.
- Все пять MIDI преобразованы штатным Java-синтезатором в WAV; оригинальные условия смены музыки исполняются из JAR.

## Проверки

`python3 tools/check_project.py --smoke`

Нужны Java 17, Python 3 с Pillow и Godot 4.7.2. Инструменты разработки не требуются пользователю самостоятельной macOS-сборки. Проверки включают побайтовую обратную сборку карты и меню, все спрайты, неизменность JAR, запуск игры, сохранение и детерминированное повторение действий.

Независимый эталон запускает **неизменённые class-файлы настоящей JVM** с небольшими заменами платформенных Java ME API. 15 сценариев и 1431 сравнение совпали. Это доказательство выбранных алгоритмов, а не доказательство полного прохождения всех концовок.

## Исходные данные и продолжение

- `PROGRESS.md` — выполненное и фактические проверки.
- `REVERSE_ENGINEERING.md` — подтверждённые форматы и алгоритмы.
- `ORIGINAL_PARITY.md` — матрица соответствия.
- `REMAINING_WORK.md` — незавершённые требования и точка продолжения.
- Локальные `research/INVENTORY.md`, `research/CLASS_METHOD_INDEX.md` содержат все файлы и методы; research не публикуется.

Материалы соседнего проекта не используются. Оригинальные байты сохранены. Исходная игра и её ресурсы остаются собственностью правообладателя; проект предназначен для локального персонального исследования и не подготовлен к публичному распространению.
